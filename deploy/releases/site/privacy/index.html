Privacy

Zen IDE has no telemetry, no analytics, no crash reporting and no accounts. Nothing about you, your projects or how you use the IDE is sent anywhere.

Editing, navigation, Git on your own repositories, run and debug work offline. Below is every network call the IDEs and Zen Toolbox make, and how to turn it off. Every call follows the IDE's proxy setting; downloads of IDEs and plug-ins are signed and checked. When an internal error is reported, the IDE only opens your browser with a prefilled issue: nothing leaves until you submit it yourself.

In the background

Pictures of commit authors

The Git log and graph show the authors' pictures. To gravatar.com goes a SHA-256 of the author's e-mail address; for a repository on a GitLab server, that server is asked with the e-mail address itself; for github.com, the user name of a GitHub no-reply address. Found pictures are kept on your computer.

On by default. Turn off: Settings → Version Control → Git Workspace → Show the authors' pictures.

Go dependency updates

Newer versions of the modules in an open go.mod, at most once an hour, from your GOPROXY (by default proxy.golang.org) and go.dev. Private modules (GOPRIVATE, GONOPROXY) are never asked about.

On by default. Turn off: Settings → Go → Check dependencies for updates.

Go vulnerability checks

The Go vulnerability database (vuln.go.dev) is downloaded and matched on your computer; only advisories that apply are looked up at api.osv.dev for their severity. The reports are licensed under CC BY 4.0.

On by default. Turn off: Settings → Go → Check dependencies for known vulnerabilities.

Updates of the IDEs and Zen Toolbox

Zen Toolbox, and an IDE installed by it, read the signed list of releases from ide.ifzenelse.space at start and every 30 minutes. Nothing but the request is sent. They download only when you click Install or Update, unless you choose automatic updates.

Turn off in Zen Toolbox: "toolbox.updates.check": "manual" in its settings file. In an IDE: start it with ZEN_RELEASES=none.

Plug-in updates

At start an IDE reads the signed plug-in catalog from ide.ifzenelse.space and updates the plug-ins you have, except those that bring database drivers. Nothing but the request is sent.

Turn off: start the IDE with ZEN_PLUGINS_CATALOG=none.

Maven and Gradle dependencies, Spring Boot support dates

Search, newer versions and vulnerabilities of Maven and Gradle dependencies (search.maven.org, repo.maven.apache.org, the repositories of your build, api.osv.dev), and Spring Boot support dates (api.spring.io).

Off by default. Settings → Build Tools.

Only when you ask

  • Installing IDEs and plug-ins, the plug-in Marketplace (ide.ifzenelse.space).
  • Installing a language server: its download, or the npm, go install, cargo install or rustup the IDE starts.
  • Download JDK (api.adoptium.net, with your operating system and processor); downloading Ant, Maven, Gradle or JaCoCo.
  • New Project generators that use a service, such as Spring Initializr (start.spring.io) with your form choices. Turn off: Settings → System Settings → Project Generators.
  • Remote images in the Markdown preview, only from hosts you allow for the project.
  • The HTTP Client, database connections, Git fetch, pull and push, the proxy's Check connection: to the servers you choose.

Builds you start (Maven, Gradle, npm, cargo, go) download from their own repositories by their own rules.
