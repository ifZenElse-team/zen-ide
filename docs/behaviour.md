# The interface specification

> **Last updated:** 2026-11-26 · **Rules:** [ADR-0002](adr/0002-open-source-clean-room-pure-rust.md), [ADR-0280](adr/0280-clean-room-process.md)

This document tracks the Zen IDE interface: how a screen or component is specified and checked, and
the state of each one. The specifications are in `docs/behaviour/`, in our own words: the behaviour,
metrics, menus and shortcuts we build.

## 1. Scope

Every Zen IDE shares one frame, so one specification covers GoGarden, RustRonin, WebWave and
JvmJizo, in the Zen Dark and Zen Light themes with the default fonts. Zen Toolbox
has its own notes and its own colours ([ADR-0016](adr/0016-toolbox-colour-scheme.md)).

## 2. Method

For each component:

1. **Specify.** Write sizes, paddings, row heights, radii, colours and fonts in
   `docs/behaviour/<component>.md`, in our own words.
2. **Describe behaviour.** Keyboard, mouse, focus, speed search, empty states, error states.
3. **Implement** from the notes only. The clean-room rules are in
   [ADR-0002](adr/0002-open-source-clean-room-pure-rust.md): nothing is copied from another
   product, and no other product is named.
4. **Verify.** Take a snapshot of our window (`ZEN_DATA_DIR=$(mktemp -d) ZEN_UI_SCREENSHOT=out.png
   gogarden <project>` writes one and quits; a snapshot start never hands its project to a running
   IDE, and the throwaway data folder keeps your settings and recent projects out of it) and
   check it against the notes; record remaining differences as defects. Views and components also
   render offscreen, without a window or a GPU (`zen_ui::offscreen`): `cargo run -p zen-ui --example
   components -- <folder>` writes the base components at 100% and 200%, and the tests in
   `crates/platform/ui/tests/` check them pixel by pixel.

Text rendering was checked this way in the egui spike
([behaviour/egui-spike.md](behaviour/egui-spike.md), ADR-0054); `cargo run -p zen-ui --example
text_rendering -- <folder>` draws the editor's and the UI's text at 100% and 200% for such checks.

The Database workspace has a model of its own, specified in
[behaviour/ide/database.md](behaviour/ide/database.md).
